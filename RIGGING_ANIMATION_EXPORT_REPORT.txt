2. MODULE IMPLEMENTATION
--------------------------------------------------------------------------------

2.1 RIGGING - src/engine/rigging/skeleton.ts
    Status: existed as an uncommitted WIP before this task; completed and
    hardened here.
      - THREE.Bone tree (21-bone humanoid generator, add/remove/reparent bones)
      - THREE.Skeleton bound to the mesh, THREE.SkinnedMesh replaces the plain
        Mesh while the SceneObject wrapper is preserved
      - THREE.SkeletonHelper visualisation (removed automatically during export)
      - Automatic weight binding: every vertex is bound to the 4 nearest bone
        segments with inverse-square falloff, weights normalised to 1.0
      - Manual weight painting (radius + strength, shift = subtract)
      - Bone posing through the transform gizmo, rest-pose capture/reset
      - Serialization: bone hierarchy + transforms + skinIndex/skinWeight arrays
    Changes made in this task:
      - Mesh -> SkinnedMesh and back now preserve the sibling index, so the
        hierarchy/ordering in the scene graph does not jump on bind/unbind
      - The bound node carries userData.rigName, exposed as SceneObject.rigName
      - New getter skeletonInstance exposes the live THREE.Skeleton
      - SceneObject gained isSkinned / rigName so the UI and exporter can tell
        a rigged object from a plain mesh without type casts

2.2 ANIMATION - src/engine/animation/animation-system.ts  (NEW)
      - THREE.AnimationMixer rooted at the scene (covers both graph objects and
        rig bones, which live in different branches of the scene tree)
      - THREE.AnimationClip + THREE.KeyframeTrack
          * position -> THREE.VectorKeyframeTrack
          * scale    -> THREE.VectorKeyframeTrack
          * rotation -> THREE.QuaternionKeyframeTrack (track path is
            ".quaternion" because GLTFExporter only maps "quaternion" to a
            glTF rotation channel - using ".rotation" would silently drop the
            track on export)
      - Targets: scene objects (by SceneObject id) and bones (by bone name)
      - Transport: play / pause / stop / loop toggle / frame scrubbing
      - Scrubbing uses action.paused + action.time + mixer.update(0), the
        three.js idiom that applies a pose at an exact time without advancing
        the clock; pause freezes the clock, stop rewinds to 0
      - Clip management: create, select, delete, duration/fps, keyframe add and
        remove at the playhead
      - Serialization: SerializedAnimationClip[] with flat times/values per
        track, JSON round-trip safe

2.3 EXPORT - src/engine/export/  (NEW FILES)
      - export-manager.ts   ExportManager + ExportFormat ('glb'|'gltf'|'obj'|'stl')
          * GLB  : GLTFExporter binary:true  -> Blob (model/gltf-binary)
          * GLTF : GLTFExporter binary:false  -> JSON Blob (model/gltf+json)
          * both receive the animation clips, so skeletons and animations are
            written into the file by the stock three.js exporter
          * the SkeletonHelper is removed while exporting (rig.beginExport /
            rig.endExport) so helper lines never end up in the model
      - obj-exporter.ts     OBJExporter wrapper (geometry only)
      - stl-exporter.ts     STLExporter wrapper, binary STL
            (three returns a DataView for binary STL, not an ArrayBuffer -
            handled explicitly, otherwise the file was a 20-byte "[object
            DataView]" string)
      - file-download.ts    downloadBlob()
          1. native bridge  window.AI3DSaveFile(filename, base64, mime) or
             window.AI3DSaveFile.saveFile(...)  -> used by the Android host
          2. blob URL + <a download>  -> works in desktop browsers and in the
             Chrome-based Android WebView
          3. data-URI fallback if the blob path throws
          The object URL is revoked after 15 s instead of immediately, because
          revoking right after click() cancels the download on Android WebView.

8. APK GENERATION - REMAINING STEPS
--------------------------------------------------------------------------------
  Requirements: Android SDK platform 36 + build-tools, JDK 17, ANDROID_HOME set.
                 compileSdkVersion 36, targetSdkVersion 36, minSdkVersion 24.

  1) Build the web bundle
         npm install
         npm run build                 # writes dist/

  2) Point the Android project at the SDK (file is git-ignored)
         printf 'sdk.dir=/path/to/Android/Sdk\n' > android/local.properties

  3) Sync the bundle and plugins into the native project
         npx cap sync android

  4) Debug APK
         cd android && ./gradlew assembleDebug
         -> android/app/build/outputs/apk/debug/app-debug.apk

  5) Release APK (needs a signing config in
     android/app/build.gradle; add keystore.properties + release signingConfig)
         cd android && ./gradlew assembleRelease
         -> android/app/build/outputs/apk/release/app-release.apk

  6) Install on a device
         adb install -r android/app/build/outputs/apk/debug/app-debug.apk

  7) On-device check
         - open the Export menu and export one .glb, one .gltf, one .obj, one .stl
         - confirm the file lands in the app download folder (Toast shows the path)
         - create a rig, bind a mesh, record keyframes, scrub and play
         - save the project and reload it: bones, weights and clips must return

9. REMAINING ISSUES / RISKS
--------------------------------------------------------------------------------
  * No APK was produced: the Android SDK is not installed on this machine, so
    the Java bridge and the Gradle build are unverified.
  * The native save hook writes to the app-private external files directory, not
    the public Downloads collection. A MediaStore implementation would be
    needed for the file to appear in the system Downloads UI.
  * OBJ and STL are geometry-only formats by definition: no skeleton, no
    animation, no materials. They export the posed mesh.
  * Weight painting samples vertices in bind pose. Repainting after posing the
    rig requires resetting to the rest pose first (known shortcut, marked in
    the source).
  * src/platform/storage.ts is still deleted in the working tree (pre-existing,
    not part of this task) - nothing in the rigging/animation/export path uses
    it.
  * A parallel session left other uncommitted work in the tree (src/ai/*,
    ai-backend/, RiggingPanel.ts, ai-backend server). It was not reviewed here.
